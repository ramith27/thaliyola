Your team's knowledge, in every Claude session

Thaliyola is a shared knowledge base for Claude Code and claude.ai. Docs, decisions, API contracts, incidents and past investigations live in one place. Agents write them, people review them, and every session on the team starts out knowing them.

തളിയോല

Thaliyola is Malayalam for the palm-leaf manuscripts Kerala used to write knowledge down and keep it for the next generation. It's the same idea for a team that works with AI: what one session learns, the next one already knows.

How it works

The server keeps the knowledge. Claude does the thinking.

Thaliyola runs no language model. Your Claude clients reason; Thaliyola stores, searches, checks and versions what they find, and people decide what gets published.

Connect Claude

Add Thaliyola to Claude Code or claude.ai as a remote MCP server. The Claude Code plugin loads the project's context at the start of every session.

Agents write, people review

Sessions save what they learn: findings, decisions, runbooks, contracts. Agent-written content waits in Review until someone on the team approves it.

Every session knows

The next session, on any laptop, searches the team's knowledge first. When it changes, the people and codebases that depend on it hear about it.

# Connect Claude Code to your Thaliyola
claude mcp add --transport http thaliyola https://thaliyola.example.com/mcp \
  --header "Authorization: Bearer $THALIYOLA_TOKEN"
Features

Knowledge that reaches people when it matters

Sessions that ask each other

Your backend session can ask the frontend team's session how the timeline reads order events, and get an answer from code that's actually open.

  • Ask a person, a project, everyone listening, or whoever knows the topic best, from an experts map built from who wrote, reviewed and answered what
  • Ask from Slack with /thaliyola, and get the answer in the thread
  • Claim the files you're changing so two sessions don't collide
  • Hand work over to a teammate with a summary and next steps

Pull request briefings

When a pull request opens, Thaliyola comments with what the team already knows about the files it touches.

  • Docs that describe the changed code and may need updating
  • API contracts and the teams that consume them
  • Known issues, open vulnerabilities and design drift in those files

Incidents with a timeline that fills itself

Declare an incident from the app, from Claude, from Slack or from a Sentry alert. Everyone in the project hears about it, including their Claude sessions.

  • Notes, merged PRs, Sentry events and sessions' answers land on the timeline
  • Resolving it drafts the RCA for review
And more

Everything a team's knowledge needs

Knowledge graph

Projects, components, contracts and the items that depend on them. A change reaches every consumer as an impact notice.

Design systems

Tokens a project inherits from the Library, contrast checks, Figma sync, and drift reports from the code.

Security

Vulnerabilities in your dependencies, SBOMs and licences, and a fix-it prompt for Claude.

Weekly project briefs

What happened: incidents, decisions, new knowledge, pull requests. By email and Slack to people who watch the project.

Decisions that stay true

Design docs, contracts and decisions per project. Decisions get a revisit date, and new ones are checked against the old ones for conflicts.

A guide built in

Every feature, whether it's switched on, how to use it and every command, in the app itself.

Principles

Built for teams that care where their knowledge lives

Your server, your data

Self-hosted on your own machine or cloud, with Postgres. Nothing leaves it unless you connect it.

People approve

Agent-written content goes through review before it's published. Every change is versioned.

Permissions everywhere

Spaces, project visibility and roles apply to people, Claude sessions, Slack and webhooks alike.

No model on the server

Search by meaning runs a small local embedding model. The reasoning stays in the Claude you already use.

Self-host

Running in minutes

Docker Compose, or a native install on Debian or Ubuntu with systemd, daily backups, off-site copies and monthly restore checks. Sign in with passwords, Google, Okta, Entra or Cloudflare Access.

Docker

Thaliyola and Postgres 16 with pgvector.

git clone https://github.com/ramith27/thaliyola
cd thaliyola && cp .env.example .env
docker compose up -d --build

Native install

One script installs Node, Postgres and the service, and prints your admin password.

git clone https://github.com/ramith27/thaliyola
cd thaliyola
sudo ADMIN_EMAIL=you@example.com \
  deploy/native/install.sh
